Paid API tools for ElizaOS agents (x402 · Base USDC)

ElizaOS agents are crypto-native by design — they already hold wallets and transact on-chain. x402 is the HTTP-native protocol that turns any RAEN endpoint into pay-per-call USDC on Base: a request without payment gets a 402 challenge; your agent signs the challenge (EIP-3009 transferWithAuthorization — not EIP-3005, a common wrong citation in older client examples) with its Base wallet and re-sends with a PAYMENT-SIGNATURE header. No API keys, no signups, no monthly plans.

Two-POST payment flow (same for every endpoint)

import json, aiohttp

async def x402_call(url: str, body: dict, sign_challenge) -> dict:
    async with aiohttp.ClientSession() as s:
        # 1) trigger the challenge
        async with s.post(url, json=body) as r:
            if r.status != 402:
                return await r.json()
            challenge = json.loads(r.headers["payment-required"])  # accepts[]
        # 2) sign the exact-scheme challenge with the agent's Base wallet
        #    (EIP-3009 transferWithAuthorization), then re-send
        sig = await sign_challenge(challenge)
        async with s.post(url, json=body, headers={"PAYMENT-SIGNATURE": sig}) as r2:
            return await r2.json()

Any EIP-3009 signer works (viem signTypedData, ethers signTypedData, or an agent-account signer). Alternative: RAEN's Bearer-gated MCP gateway at https://raen-mcp-gateway.fly.dev/mcp — free dev key via POST /keys/request (30-day key, email verification), same tools over MCP; ElizaOS connects to MCP servers through its MCP client plugin.

ElizaOS plugin action (TypeScript, @elizaos/core 1.x)

Package the paid call as a plugin Action so the agent's planner can choose it and you control spend in validate:

import type { Action, IAgentRuntime, Memory, State } from "@elizaos/core";

const LAWDATA_URL = "https://royal-ruby-x402.fly.dev/api/law-lookup";

async function x402call(url: string, body: unknown, runtime: IAgentRuntime) {
  const r1 = await fetch(url, { method: "POST", headers: { "content-type": "application/json" }, body: JSON.stringify(body) });
  if (r1.status !== 402) return r1.json();
  const challenge = JSON.parse(r1.headers.get("payment-required")!);
  // sign challenge.accepts[0] per EIP-3009 with the runtime's Base wallet
  const sig = await runtime.wallet.signChallenge(challenge);
  const r2 = await fetch(url, { method: "POST",
    headers: { "content-type": "application/json", "PAYMENT-SIGNATURE": sig },
    body: JSON.stringify(body) });
  return r2.json();
}

export const lawLookup: Action = {
  name: "RAEN_LAW_LOOKUP",
  similes: ["LOOK_UP_CONSUMER_LAW", "FCRA_CITATION"],
  description: "Look up US consumer-law citations (FCRA/FDCPA/TILA/UDAP). Settles $0.05 USDC on Base per call.",
  validate: async (_rt: IAgentRuntime, message: Memory) =>
    /fcra|fdcpa|tila|udap|dispute|credit report|consumer law/i.test(message.content.text ?? ""),
  handler: async (runtime: IAgentRuntime, message: Memory, _state?: State) => {
    const result = await x402call(LAWDATA_URL, { topic: message.content.text }, runtime);
    return { text: JSON.stringify(result).slice(0, 4000) };
  },
  examples: [],
};

export const raenPlugin = {
  name: "raen-paid-tools",
  description: "RAEN x402 paid endpoints (USDC on Base, pay per call)",
  actions: [lawLookup],
};

One Action per domain keeps the planner from firing paid calls on unrelated prompts; the validate regex is your spend guardrail. Each settlement's response carries the on-chain tx evidence — log it for your own audit trail.

Why this fits ElizaOS specifically

  • Wallet-first: most ElizaOS deployments already run an EOA/signer — x402 needs exactly that, nothing else. No vendor account, no key provisioning.
  • Character-driven spend control: put per-action price disclosure in the action description (as above) so the character's reasoning sees the cost before the handler settles USDC.
  • Per-call economics match agent lifecycles: long-running autonomy loops pay pennies per step instead of burning a $20/mo SaaS seat.
