Paid API tools for Cursor (x402 · Base USDC)

Cursor — the AI code editor with agent mode — runs terminal commands and installs MCP servers natively, so its agent can both hold paid tools (MCP) and execute the x402 payment dance itself (it can run the curl/sign/retry loop in the integrated terminal and watch the challenge in real time). Cursor itself cannot sign a 402 challenge, so the payment rail is either a Bearer key (Path 1) or a wallet script the agent runs (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended): RAEN MCP gateway in ~/.cursor/mcp.json

The gateway exposes 5 tools over streamable HTTP MCP: raen_law_lookup ($0.05), raen_ticker_analysis ($0.05, synthetic demo — see caveats), raen_dispute_letter ($0.10), raen_image_generate ($0.01), raen_contract_analysis ($0.05). The Bearer key gates the whole server and settles per call — the key is the billing rail. Get a free 30-day dev key first:

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then register the remote MCP server (File → Cursor Settings → MCP, or edit the file directly):

{
  "mcpServers": {
    "raen": {
      "url": "https://raen-mcp-gateway.fly.dev/mcp",
      "headers": {
        "Authorization": "Bearer <your-30-day-dev-key>"
      }
    }
  }
}

Tools appear under raen__raen_law_lookup etc. in agent-mode's tool list. Keep the key out of repos and synced dotfiles — put it in an environment variable your shell exports if your Cursor version supports header substitution.

Path 2 (wallet-native): the two-POST x402 flow, run by the agent

Cursor's agent executes shell commands — hand it the cookbook recipe 02 pattern and it can run the whole flow autonomously:

POST https://royal-ruby-x402.fly.dev/api/law-lookup   (no payment header)
← 402 + payment-required header (base64 JSON challenge: amount, payTo, asset)
# sign USDC transferWithAuthorization (EIP-3009) for that exact amount with viem/web3.py
POST same URL + x-payment header (base64 signed JSON)
← 200 + result body + x-payment-response (settlement tx on Base)

Load a Base wallet key into the environment the way your setup allows (env var, secret store) — never hardcode it in a repo file. Spend control: Cursor's per-command approval prompts let you review the signing command before it runs, which is a natural budget gate. A minimal Python signer with viem/web3.py is ~30 lines; recipe 02 has it verbatim.

Dispatch-first pattern (cheapest way to explore)

If you don't know which service you need, call dispatch ($0.50) with the intent; it routes to the right endpoint and tells you the cost before you spend more.

Why this works well specifically in Cursor

  • Agent mode already runs bash/python — the two-POST flow is just another command chain it can inspect, debug, and re-run.
  • .cursor/rules can enforce a spend guardrail in plain text (e.g. "never sign an x402 challenge above $1.00 without asking") — the agent reads it every session.
  • Per-call micro-prices mean a full research or dispute task costs cents — no subscription, no key-of-ours.
