Paid API tools for Claude Code (x402 · Base USDC)

Claude Code — Anthropic's agentic CLI — executes shell commands and edits files natively, which makes it one of the easiest hosts for paid x402 tools. It has two distinct payment paths: the RAEN MCP gateway via a one-line claude mcp add (Path 1, no wallet needed — the Bearer dev key is the billing rail), or the raw two-POST x402 flow run from its own Bash tool with your wallet (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended, no wallet): RAEN MCP gateway via claude mcp add

First get a free 30-day dev key (email-verified, self-serve):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then register the gateway with Claude Code in one command (user scope so every project gets it):

claude mcp add --transport http --scope user raen \
  https://raen-mcp-gateway.fly.dev/mcp \
  --header "Authorization: Bearer $RAEN_KEY"

Keep the key out of dotfiles: export RAEN_KEY in your shell profile (or Claude Code's env settings block), never in a committed file. Tools appear as mcp__raen__raen_law_lookup, mcp__raen__raen_ticker_analysis, mcp__raen__raen_dispute_letter, mcp__raen__raen_image_generate, mcp__raen__raen_contract_analysis ($0.05 / $0.05 / $0.10 / $0.01 / $0.05). The gateway's 402 paid gate is what makes the Bearer key the billing rail — Claude Code pays per MCP tool call without ever touching a wallet. Verify with /mcp inside Claude Code.

Path 2 (wallet-native): the two-POST x402 flow from the Bash tool

Claude Code runs bash and python natively, so it can execute the raw x402 flow directly — hand it cookbook recipe 02 and it writes the signer verbatim (~30 lines, web3.py):

POST https://royal-ruby-x402.fly.dev/api/law-lookup   (no payment header)
← 402 + payment-required header AND body (base64 JSON: amount, payTo, asset)
# sign USDC transferWithAuthorization (EIP-3009) for that exact amount
POST same URL + x-payment header (base64 signed JSON)
← 200 + result body + x-payment-response (settlement tx on Base)

Claude Code-specific conversion details:

  • Permission prompts are the natural spend gate — every signing command hits an approval prompt by default. Never allowlist the signer command (settings.json permissions) or a wildcard bash rule; leave payments on the interactive path.
  • Load the wallet key as an env var (export RAEN_WALLET_KEY=...) and add wallet files to .gitignore — never let the agent write a key into a file it can commit.
  • Put the budget rule in CLAUDE.md (read at session start): e.g. "never sign an x402 challenge above $1.00 without asking me first". Claude Code honors it reliably, and the permission prompt is the hard backstop.

Dispatch-first pattern (cheapest way to explore)

If you don't know which service you need, call dispatch ($0.50) with the intent; it routes to the right endpoint and states the downstream price before you spend more. In Path 1 the same routing is a natural Claude Code plan-step: ask for the dispatch tool result first, then approve the specific downstream call.

Why this works well specifically in Claude Code

  • The Bash tool executes the whole two-POST flow with zero extra scaffolding — recipe 02 in the repo is enough.
  • CLAUDE.md is a plain-text spend guardrail read every session, and permission prompts are the enforcement backstop — the cheapest possible budget control with teeth.
  • Per-call micro-prices mean a full research or dispute task costs cents — no subscription, no key-of-ours beyond the free 30-day dev key.
