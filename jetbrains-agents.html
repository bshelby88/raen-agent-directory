Paid tools for JetBrains agents (AI Assistant & Junie)

IntelliJ IDEA, PyCharm, WebStorm and friends ship a native MCP client (Settings → Tools → MCP Servers) and Junie — JetBrains' coding agent — can run terminal commands. Two real paths to pay-per-call APIs, both work today:

PATH 1 — no wallet, recommended RAEN MCP gateway as a remote MCP server in IDE settings. Free 30-day Bearer dev key via POST /keys/request — no credit card, no wallet install; the key IS the billing rail.

PATH 2 — wallet-native Raw two-POST x402 flow run from the IDE's built-in terminal by Junie or AI Assistant. Sign EIP-3009 transferWithAuthorization per cookbook recipe 02. JetBrains-specific spend guardrails below.

Path 1 — RAEN gateway as a remote MCP server (no wallet)

Get a free dev key first:

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@yourcompany.com"}'
# verification email → open the link → 30-day Bearer key

Then in the IDE: Settings → Tools → MCP Servers → Add, choose a remote server, set:

URL:     https://raen-mcp-gateway.fly.dev/mcp
Type:    Streamable HTTP
Headers: Authorization: Bearer RAEN_YOUR_KEY

The gateway's 5 tools appear in AI Assistant / Junie tool calls as raen_law_lookup, raen_analyze_contract, raen_generate_image, raen_analyze_ticker, raen_dispatch. Tool annotations (readOnlyHint: true, destructiveHint: false) are live on all 5 tools — trust surfaces that read annotations treat them as read-only lookups — but each call is a metered paid API call behind the 402 gate; the Bearer key is the billing rail.

Version note: remote (Streamable HTTP) MCP servers are supported in recent 2025.x IDE builds — if your build only offers local command servers, upgrade or use Path 2. Keep the dev key out of the repo: it lives in IDE settings, never in committed files.

Path 2 — wallet-native: the two-POST x402 flow from the IDE terminal

POST unpaid → HTTP 402 with a payment-required challenge header → sign EIP-3009 transferWithAuthorization for USDC on Base → retry POST with the x-payment header → 200 + paid result. Full client code: cookbook recipe 02 (Python client).

import requests
r = requests.post("https://contract-eye-x402.fly.dev/api/analyze-contract",
                  json={"text": contract_text})
if r.status_code == 402:
    payment = sign_challenge(r.headers["payment-required"], private_key)
    r = requests.post(same_url, json=same_body,
                      headers={"x-payment": payment})
print(r.json())

JetBrains-specific spend guardrails (do these before Path 2):

  • Junie: keep "auto-run commands" OFF / restricted — the per-command approval prompt is your hard spend backstop; never allowlist the signer command.
  • Put a budget rule in .junie/guidelines.md (Junie's project guidelines, read every run): e.g. "stop after $0.50 of paid API calls per session; always print the price from the 402 quote before spending".
  • Wallet private key as an env var only; never let the agent write it into a project file or commit it.
  • Start on the cheapest endpoints ($0.01–$0.05) to validate the flow before anything pricier.
  • Use a dedicated thinly-funded wallet for agent spending, not your primary key.
