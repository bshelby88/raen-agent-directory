CrewAI Flows on paid rails

Companion page for the CrewAI Flows feature (the event-driven, structured-orchestration layer — not Crew kickoffs). This extends Paid tool calls in CrewAI (tool wrappers) and CrewAI recipes (end-to-end crews) to the Flows programming model, where spending decisions are made at state transitions — the natural place for a budget gate.

60-second first paid call (no wallet): get a free 30-day dev key, then use the RAEN MCP gateway as a Flows tool — 
curl -s -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' -d '{"email":"you@example.com"}'
# then in Flow code: any HTTP client POSTs to https://raen-mcp-gateway.fly.dev/mcp
# with Authorization: Bearer <key from your email>
The first call is charge-and-rebate on the API paths (you pay the challenge, the rebate returns it) — net $0 on the first call of each service.

Why Flows is the right place for paid tools

  • @listen / @persist gates: paid calls live inside a @listen("state_ready") method, so a single wallet check runs before any spend — the flow structure is the spend guardrail.
  • Structured state: spent amounts accumulate on a Pydantic state field (total_spent_usd), giving you a per-flow budget ledger for free.
  • Router methods: decide between the cheap tool ($0.05) and the premium tool ($5.00) in @router — pricing is a routing decision, not a prompt hope.

Pattern: a paid call inside a Flow state transition

from crewai.flow import Flow, listen, start
from pydantic import BaseModel
import json, urllib.request

GATEWAY = "https://raen-mcp-gateway.fly.dev/mcp"

class S(BaseModel):
    topic: str = "credit-report disputes"
    total_spent_usd: float = 0.0

def law_lookup(topic: str) -> dict:
    body = json.dumps({"jsonrpc":"2.0","id":1,"method":"tools/call",
        "params":{"name":"raen_law_lookup","arguments":{"topic":topic}}}).encode()
    req = urllib.request.Request(GATEWAY, data=body, method="POST",
        headers={"Content-Type":"application/json",
                 "Authorization": f"Bearer {os.environ['RAEN_KEY']}"})   # key from POST /keys/request — never committed
    return json.load(urllib.request.urlopen(req))

class DisputeFlow(Flow[S]):
    @start
    def prepare(self):
        return self.state.topic

    @listen(prepare)
    def cite_laws(self, topic):
        if self.state.total_spent_usd > 1.00:      # budget gate at the transition
            raise RuntimeError("Flow budget exhausted")
        out = law_lookup(topic)
        self.state.total_spent_usd += 0.05
        return out["result"]

DisputeFlow().kickoff()

Pattern 2: wallet-native path (raw x402, no gateway)

Flows running on infra with a signing key can skip the gateway and answer the 402 challenge directly — the same two-POST EIP-3009 flow documented in cookbook recipe 02. Flows-specific guardrails:

  • Run the signer in one @listen method only; keep private_key in an env var (os.environ["SIGNER_KEY"]), never in Flow state — Flow state can be serialized/persisted.
  • @persist serializes state to disk: make sure the state schema excludes any key material.
  • Put the budget check BEFORE the paid call in the same method — a router that already spent can't un-spend.

Honest caveats (TRUTH law)

  • royal-ruby runs a disclosed A/B price test — your wallet may see $0.03 instead of $0.05; the 402 challenge always states the exact amount.
  • tradingagents and staci-tradingagents disclose that their payloads are synthetic demo data.
  • contract-eye and briefsnap advertise degraded fallback modes when their LLM key is unhealthy.
  • Per-call prices are the live manifest/402-quote prices as of 2026-11-16; verify the challenge amount at call time.
