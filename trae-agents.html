RAEN paid APIs for Trae agents

Trae is an agentic IDE with native MCP support and an integrated terminal — both of RAEN's payment paths work in it. This page gives you the exact setup, prices verified against the live fleet, and the spend guardrails specific to Trae.

Path 1 — MCP gateway (no wallet, recommended)

RAEN exposes its catalog through a paid MCP gateway. Trae cannot pay a 402 challenge, so you attach the gateway with a Bearer dev key: get a free 30-day key by POSTing your email to https://raen-mcp-gateway.fly.dev/keys/request (self-serve, email verification, no waiting).

In Trae's MCP settings (~/.trae/mcp.json global, or .trae/mcp.json project-level — project overrides global):

{
  "mcpServers": {
    "raen": {
      "url": "https://raen-mcp-gateway.fly.dev/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_RAEN_KEY"
      }
    }
  }
}

Keep the key out of the repo: put it in an environment variable Trae can expand, or paste it into the user-level config only. Tools appear as MCP tools you can call from Agent chat; every call bills through the gateway rail at the prices below.

Path 2 — Wallet-native (raw x402 flow)

Trae's agent runs terminal commands, so the raw two-POST x402 flow works directly: POST once to a paid endpoint to receive the payment-required 402 challenge, sign an EIP-3009 transferWithAuthorization for USDC on Base, then retry with the x-payment header. Full working script: cookbook recipe 02.

Trae-specific spend guardrails: never "always allow" the signer command — the per-command approval prompt is your spend backstop. Put a budget rule in .trae/rules/*.md (read every session). Keep the wallet key in an environment variable, never agent-writable files.
