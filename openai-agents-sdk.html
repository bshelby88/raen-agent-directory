Give your OpenAI Agents SDK agent a wallet: per-call tools, priced in cents

The Agents SDK is built around the idea that a model should decide when a tool is worth calling — but the tool itself usually drags in API keys, rate limits, and monthly minimums for a function the agent calls twice a week. The endpoints below are plain HTTPS POSTs that cost $0.01–$1.50 per call, settled in USDC on Base via the x402 protocol. The payment IS the auth — a @function_tool wrapper is ~30 lines and needs no account with anyone.

Wrapping one as a function_tool

x402 is a two-POST flow: the first POST returns 402 with a payment-required header (a challenge naming price, payee, and network); your wallet signs a USDC transferWithAuthorization on Base and you re-send with a PAYMENT-SIGNATURE header. The x402 python SDK handles the signing. The openai-agents SDK just sees a normal async tool:

from agents import function_tool
import httpx, json, base64

@function_tool
async def analyze_contract(text: str) -> str:
    """Analyze contract text for risky or one-sided clauses.
    Returns risk score, flagged clauses with severity and suggested
    edits. Costs $0.05 USDC per call."""

    url = "https://contract-eye-x402.fly.dev/api/analyze-contract"
    body = {"text": text}

    # 1) First POST — read the 402 challenge
    async with httpx.AsyncClient(timeout=60) as c:
        r = await c.post(url, json=body)
        if r.status_code != 402:
            return json.dumps({"error": "unexpected status", "status": r.status_code})
        challenge = json.loads(base64.b64decode(r.headers["payment-required"]))
        accepts = challenge["accepts"][0]   # scheme exact, eip155:8453, USDC

        # 2) Sign the USDC transferWithAuthorization (x402 SDK or your signer)
        sig = await sign_x402_payment(accepts, from_key=AGENT_KEY)

        # 3) Re-send with PAYMENT-SIGNATURE
        r2 = await c.post(url, json=body, headers={"PAYMENT-SIGNATURE": sig})
        return r2.json() if r2.status_code == 200 else json.dumps({"error": r2.status_code})

Hand the tool to Agent(name=..., tools=[analyze_contract]) and the agent only spends when the task actually warrants $0.05 — every payment is an on-chain USDC transfer you can reconcile. The same endpoints also work from an MCP bearer-key gateway if you prefer key-auth to wallet-auth (the Agents SDK speaks MCP natively via MCPServerStreamableHttp), and from LangChain/LangGraph, CrewAI, or Haystack, Semantic Kernel and n8n with the identical URLs.

Why pay-per-call beats a key/subscription for agent tools

  • Spend follows use: a 100-call run costs ~$5 on the micro-priced endpoints; an idle month costs $0.
  • No credential sprawl: no per-vendor API keys to store, rotate, or leak in your agents' env.
  • On-chain audit trail: every tool call that cost money left a USDC transfer on Base.
  • Works for humans and agents alike: the identical URL serves an Agents SDK tool, an n8n HTTP node, or an autonomous agent with an x402 wallet.

Honest caveats

  • All-time fleet revenue to date: $0.10 internal test settlements; 0 external payers so far (live ledger: settlement-collector.fly.dev/ledger). You would be early.
  • Market-analysis endpoints currently return a disclosed synthetic demo payload — do not wire them into money decisions.
  • contract-eye discloses its delivery mode per response: if LLM analysis is unavailable it returns a deterministic rule-based clause scan (fields method / delivery_mode tell you which). briefsnap discloses fallback mode the same way (mode / delivery_mode).
  • The consumer-law endpoint is not legal advice; these are information-only services.
  • Network: Base (eip155:8453), USDC, scheme exact, payTo 0x9b8a…f72f — always verify against the live manifest at call time.
