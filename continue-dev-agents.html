Paid API tools for Continue.dev (x402 · Base USDC)

Continue.dev — the open-source AI code assistant for VS Code and JetBrains — is a native MCP client: its config.yaml accepts remote MCP servers by url with custom headers. That makes it a natural host for the RAEN paid-tool catalog. Two payment paths: the RAEN MCP gateway added as a remote MCP server (Path 1, no wallet needed — the Bearer dev key is the billing rail), or the raw two-POST x402 flow executed from your terminal with your wallet (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended, no wallet): RAEN MCP gateway in Continue's config.yaml

First get a free 30-day dev key (email-verified, self-serve):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then add the gateway to ~/.continue/config.yaml (or your project's .continue/config.yaml for workspace-scoped use):

mcpServers:
  - name: raen
    url: https://raen-mcp-gateway.fly.dev/mcp
    type: streamable-http
    headers:
      Authorization: Bearer YOUR_RAEN_DEV_KEY

Continue's agent mode can then call RAEN tools directly: raen_law_lookup (FCRA/FDCPA/TILA/UDAP statute citations), raen_ticker_analysis, raen_dispute_letter, raen_image_generate, raen_contract_analysis. The gateway's 402 paid gate makes the Bearer key the billing rail — Continue pays per MCP tool call without ever touching a wallet. Verify the handshake by asking Continue "list your raen tools". Note: paste the key literally or keep it in a file you never commit — treat config.yaml containing the key as a secret. If your Continue build supports env-var interpolation in headers, prefer that.

Path 2 (wallet-native): the two-POST x402 flow from your terminal

Continue's agent can write and run shell commands, so it can execute the raw x402 flow itself — hand it cookbook recipe 02 and it writes the signer verbatim (~30 lines, web3.py):

POST https://royal-ruby-x402.fly.dev/api/law-lookup   (no payment header)
← 402 + payment-required header AND body (base64 JSON: amount, payTo, asset)
# sign USDC transferWithAuthorization (EIP-3009) for that exact amount
POST same URL + x-payment header (base64 signed JSON)
← 200 + result body + x-payment-response (settlement tx on Base)
Continue-specific spend guardrails: when Continue asks for permission to run the signer command, approve that one command — never mark it "always allow": the per-command approval prompt is your hard spend backstop. Put the budget rule in ~/.continue/config.yaml system-message text (or your AGENTS.md, which Continue reads): "never sign an x402 challenge above $1.00 — ask me first". Load the wallet key as an environment variable (export RAEN_WALLET_KEY=...) rather than letting the agent write a key into any file, and keep wallet files out of git.
