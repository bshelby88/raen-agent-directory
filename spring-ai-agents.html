The x402 two-POST flow (from Java)

Every endpoint works the same way: POST without payment → receive 402 with a payment-required header (base64 JSON challenge) → pay the named amount to payTo via an EIP-3009 transferWithAuthorization on USDC (Base, chain 8453) → re-send with a PAYMENT-SIGNATURE header. The facilitator (raen-facilitator.fly.dev) verifies the signature on-chain.

record LawLookup(String topic, String state) {}
record LawResult(boolean ok, Object data) {}

@Bean
public FunctionCallback lawLookup() {
    return FunctionCallback.builder()
        .function("lawLookup", LawLookup.class)
        .description("Look up a US statute citation. Costs $0.05 USDC on Base via x402.")
        .func((req) -> {
            HttpRequest first = HttpRequest.newBuilder(
                URI.create("https://royal-ruby-x402.fly.dev/api/law-lookup"))
                .header("Content-Type", "application/json")
                .POST(HttpRequest.BodyPublishers.ofString(new ObjectMapper().writeValueAsString(req)))
                .build();
            HttpResponse<String> r = client.send(first, HttpResponse.BodyHandlers.ofString());
            if (r.statusCode() != 402) throw new IllegalStateException("expected 402 challenge");
            String challenge = new String(Base64.getDecoder().decode(
                r.headers().firstValue("payment-required").orElseThrow()), StandardCharsets.UTF_8);
            // 1. parse challenge JSON (accepts[].payTo, maxAmountRequired, asset)
            // 2. sign an EIP-3009 transferWithAuthorization with your Base wallet
            //    (web3j / Web3Signer — use your existing signing infra)
            // 3. re-send the identical POST with the PAYMENT-SIGNATURE header
            return x402Client.payAndSend(first, challenge, req);
        })
        .build();
}
