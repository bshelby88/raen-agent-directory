Paid API tools for Devin (x402 · Base USDC)

Devin (Cognition) — the autonomous software-engineering agent — runs in a cloud sandbox and supports custom remote MCP servers, which makes the RAEN paid-tool catalog a natural fit. Two payment paths: add the RAEN MCP gateway as a custom MCP server (Path 1, no wallet — the Bearer dev key is the billing rail), or have Devin execute the raw two-POST x402 flow in its sandbox shell with your own wallet (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended, no wallet): RAEN MCP gateway as a custom MCP server

First get a free 30-day dev key (email-verified, self-serve):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then add the gateway in Devin: Settings → Connections → MCP Servers → Add custom server (or per-session via the MCP toggle in the session sidebar), pointing at:

URL:     https://raen-mcp-gateway.fly.dev/mcp
Headers: Authorization: Bearer ***

Store the Bearer key in Devin's Secrets rather than pasting it into chat text — secrets stay out of the session transcript and any repo Devin commits to. Tools appear as raen_law_lookup (FCRA/FDCPA statute citations), raen_ticker_analysis, raen_dispute_letter, raen_image_generate, raen_contract_analyze, and the rest of the RAEN catalog.

Why the Bearer key is the billing rail: Devin cannot pay an HTTP 402 challenge itself. The gateway fronts the fleet: it presents the free 30-day dev key, and every paid call behind it is billed on the x402 rail (first-call-free charge-and-rebate applies where advertised). Devin's own spend meter (ACUs) is a separate cost — this page is about the tool cost, not Devin's compute.

Path 2 (wallet-native): the two-POST x402 flow from Devin's sandbox

Devin executes shell commands in its cloud VM, so the raw HTTP-native x402 flow works with no MCP setup at all. Have Devin run cookbook recipe 02 (Python client): POST the paid route → receive 402 with a payment-required challenge → build and sign an EIP-3009 transferWithAuthorization (USDC on Base, 6 decimals) → POST again with the X-PAYMENT header → receive the 200 with the service payload.

# Instruct Devin:
# "Run https://bshelby88.github.io/x402-cookbook/recipes/02-python-client.html
#  against https://royal-ruby-x402.fly.dev/api/law-lookup {'topic':'FCRA 605'}
#  using the wallet key in secret WALLET_PRIVATE_KEY. Print the response body."
Spend gate — read before funding anything: do not put a primary wallet key into Devin Secrets. Use a dedicated, thinly-funded key (e.g. 5 USDC) and state the exact endpoint + expected price in the prompt so the run is scoped. Devin's sandbox is an autonomous environment: the key you provide sets your exposure, and approval prompts on shell commands are the natural checkpoint — keep them on. Wallet files Devin writes in the sandbox are ephemeral, but treat any key that entered the environment as spendable-until-spent.
