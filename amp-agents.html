Paid API tools for Amp (x402 · Base USDC)

Amp — Sourcegraph's agentic coding agent (VS Code extension + autonomous CLI) — is a native MCP client and a terminal-first agent: it reads your repo, plans, and executes commands. That makes it a natural host for the RAEN paid-tool catalog. Two payment paths: the RAEN MCP gateway added as an MCP server (Path 1, no wallet needed — the Bearer dev key is the billing rail), or the raw two-POST x402 flow executed by Amp in your terminal with your wallet (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended, no wallet): RAEN MCP gateway in Amp's MCP settings

First get a free 30-day dev key (email-verified, self-serve):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request   -H 'Content-Type: application/json'   -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then register the gateway as a remote (HTTP) MCP server in Amp — see ampcode.com/manual for the exact MCP-config surface your build uses (amp mcp add or the mcpServers block in Amp's settings file):

name: raen
url: https://raen-mcp-gateway.fly.dev/mcp
type: http
headers:
  Authorization: Bearer YOUR_RAEN_DEV_KEY

Amp can then call RAEN tools directly: raen_law_lookup (FCRA/FDCPA/TILA/UDAP statute citations), raen_ticker_analysis, raen_dispute_letter, raen_image_generate, raen_contract_analysis. The gateway's 402 paid gate makes the Bearer key the billing rail — Amp pays per MCP tool call without ever touching a wallet. Verify the handshake by asking Amp "list your raen tools". Treat any settings file containing the key as a secret — never commit it; prefer env-var expansion if your build supports it.

Path 2 (wallet-native): the two-POST x402 flow via Amp's terminal

Amp writes and runs shell commands, so it can execute the raw x402 flow itself — hand it cookbook recipe 02 and it writes the signer verbatim (~30 lines, web3.py):

POST https://royal-ruby-x402.fly.dev/api/law-lookup   (no payment header)
← 402 + payment-required header AND body (base64 JSON: amount, payTo, asset)
# sign USDC transferWithAuthorization (EIP-3009) for that exact amount
POST same URL + x-payment header (base64 signed JSON)
← 200 + result body + x-payment-response (settlement tx on Base)
Amp-specific spend guardrails: when Amp asks to run the signer command, approve that one command — never configure it as always-allowed (Amp's autonomy settings are aggressive by design; the per-command approval is your hard spend backstop). Put the budget rule in Amp's rules file (which it reads every thread): "never sign an x402 challenge above $1.00 — ask me first". Load the wallet key as an environment variable rather than letting the agent write a key into any file, and keep wallet files out of git. Amp's thread sharing is on by default — keep the signer output (and any key material) out of shared threads.
