Paid API tools for Amazon Q Developer (x402 · Base USDC)

Amazon Q Developer — AWS's agentic CLI (q chat) — executes shell commands with per-command approval and speaks MCP via mcp.json, which makes it a natural host for the RAEN paid-tool catalog. Two payment paths: the RAEN MCP gateway registered in mcp.json (Path 1, no wallet needed — the Bearer dev key is the billing rail), or the raw two-POST x402 flow executed from Q's own shell with your wallet (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended, no wallet): RAEN MCP gateway in mcp.json

First get a free 30-day dev key (email-verified, self-serve):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then register the gateway in Q Developer's MCP config — ~/.aws/amazonq/mcp.json for global scope or .amazonq/mcp.json in the workspace (workspace overrides global):

{
  "mcpServers": {
    "raen": {
      "url": "https://raen-mcp-gateway.fly.dev/mcp",
      "headers": { "Authorization": "Bearer ***" }
    }
  }
}

Check your Q CLI version's support for remote HTTP servers with q mcp after editing — recent q releases accept url-based MCP servers with custom headers; if your build only lists stdio servers, Path 2 works regardless. Keep the key out of any committed file — paste the Bearer value from your inbox and treat mcp.json as a secret. Tools appear to Q as raen_law_lookup (FCRA/FDCPA statute citations), raen_ticker_analysis, raen_dispute_letter, raen_image_generate, raen_contract_analysis. The gateway's 402 paid gate makes the Bearer key the billing rail — Q pays per MCP tool call without ever touching a wallet. Verify with q mcp or by asking Q "list your raen tools".

Path 2 (wallet-native): the two-POST x402 flow from Q's shell

q chat executes bash and python directly (with approval), so it can run the raw x402 flow — hand it cookbook recipe 02 and it writes the signer verbatim (~30 lines, web3.py):

POST https://royal-ruby-x402.fly.dev/api/law-lookup   (no payment header)
← 402 + payment-required header AND body (base64 JSON: amount, payTo, asset)
# sign USDC transferWithAuthorization (EIP-3009) for that exact amount
POST same URL + x-payment header (base64 signed JSON)
← 200 + result body + x-payment-response (settlement tx on Base)
Amazon-Q-specific spend guardrails: Q asks before every shell command by default — keep it that way; per-command approval is the natural spend backstop, and q trust-ing tools or allowing all tools removes it. Load the wallet key as an env var (export RAEN_WALLET_KEY=...) and never let Q write a key into a file inside your repo. Put the budget rule in AmazonQ.md (the rules file Q reads every session): e.g. "never sign an x402 challenge above $1.00 — ask me first". Context windows are restored per chat, but the rule file loads every time.

No API keys, no accounts, per-call USDC settlement on Base.
