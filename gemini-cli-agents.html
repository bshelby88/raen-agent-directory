Paid API tools for Gemini CLI (x402 · Base USDC)

Gemini CLI — Google's open-source terminal agent — pays per call for real work: no API keys of ours, no signups, no monthly plans. Gemini CLI is MCP-native (it connects to mcpServers entries in ~/.gemini/settings.json), so the fastest path is RAEN's Bearer-gated MCP gateway as a streamable-HTTP MCP server. Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended): the RAEN MCP gateway in settings.json

The gateway exposes 5 tools: raen_law_lookup ($0.05), raen_ticker_analysis ($0.05, synthetic demo — see caveats), raen_dispute_letter ($0.75), raen_image_generate ($0.01), raen_contract_analysis ($0.05). In Gemini CLI they appear as raen__raen_law_lookup etc. — Gemini CLI prefixes tool names with the server alias.

  1. Get a free 30-day dev key (self-serve, email verification, no waiting): 
    curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.org"}'
    Rate limit 3/day/IP. The key arrives by email; export it before starting Gemini CLI.
  2. Add the server to ~/.gemini/settings.json (Windows: %USERPROFILE%\.gemini\settings.json): 
    {
  "mcpServers": {
    "raen": {
      "httpUrl": "https://raen-mcp-gateway.fly.dev/mcp",
      "headers": {
        "Authorization": "Bearer $RAEN_DEV_KEY"
      },
      "timeout": 10000
    }
  }
}
    httpUrl is Gemini CLI's streamable-HTTP transport; headers values expand $ENV_VARS from your shell, so the key stays out of the config file (same pattern the official docs show for Bearer-auth MCP servers). Restart gemini; run /mcp to confirm the raen server connected and its 5 tools listed.
  3. One-line alternative (no JSON editing): gemini mcp add --transport http raen https://raen-mcp-gateway.fly.dev/mcp --header "Authorization: Bearer <paste-key>" — the CLI flag writes the same settings entry.
  4. Ask Gemini CLI something real: "Use the raen tool to look up the FDCPA citations for repeated calls about a debt I already disputed" — it calls raen__raen_law_lookup and the gateway meters the per-call price against your dev key.

Why the header is required: the gateway is itself a paid x402 gate — a request with no Authorization gets an HTTP 402 payment challenge (scheme=exact, eip155:8453, canonical payTo). Gemini CLI cannot pay a 402 challenge itself, so the Bearer dev key is the Gemini CLI path; the key covers the tool metering instead.

Path 2: raw x402 from a shell step (wallet-native)

For headless runs, cron jobs, or when you want payment to be the wallet's signature rather than a metered key, call the endpoints directly with the two-POST 402 flow from a run_shell_command step (any EIP-3009 signer works; the challenge you receive states the exact amount to authorize):

import json, requests

def x402_call(url: str, body: dict, signer) -> dict:
    # 1) trigger the challenge
    r = requests.post(url, json=body)
    if r.status_code != 402:
        return r.json()
    challenge = json.loads(r.headers["payment-required"])  # contains accepts[]
    # 2) sign the exact-scheme challenge with your Base wallet (EIP-3009
    #    transferWithAuthorization on USDC), then re-send with the payment header
    sig = signer.sign_challenge(challenge)
    r2 = requests.post(url, json=body, headers={"PAYMENT-SIGNATURE": sig})
    return r2.json()

# Gemini CLI shell step: python scripts/x402_call.py --law-lookup "FDCPA section 1692g"

Why Gemini CLI fits

Gemini CLI's mcpServers config is exactly the RAEN gateway's interface — one JSON block and the 5 paid tools sit next to Gemini's built-ins, with per-tool confirmation prompts (/mcp to inspect) and env-var header expansion keeping the key out of dotfiles. And if you outgrow the metered key, Path 2 keeps payment wallet-native (EIP-3009) with no change to the business logic — only the signer changes.
