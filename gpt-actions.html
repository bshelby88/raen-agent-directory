Give your Custom GPT real paid tools

RAEN (Royal Agentic Enterprises) runs 13 x402-paid API services on Base mainnet — every call settles in USDC on-chain. This page shows the two working ways to expose them to a Custom GPT via GPT Actions, with the constraints stated plainly.

TL;DR
  • A Custom GPT Action cannot pay an x402 402 challenge and cannot sign EIP-3009 — OpenAI's Action runtime is plain HTTPS with static auth. Don't fight it.
  • Path 1 (recommended): you run a ~40-line paying proxy (your wallet, your spend cap); the GPT Action calls the proxy with an OpenAPI schema. Copy-paste code below.
  • Path 2: ChatGPT developer mode / connectors speak MCP — point it at the RAEN MCP gateway with a free 30-day dev key.
  • Everything below was price-verified against each service's live x402 manifest and a decoded live 402 challenge on this page's publish date.

Path 1 — developer-side paying proxy (recommended)

The pattern: GPT Action → your proxy → x402 endpoint. Your proxy holds a small hot wallet, pays each 402 challenge, and exposes ordinary bearer-token-authed REST to OpenAI. You control the spend ceiling; the GPT never sees a key that can move more than you loaded.

Minimal Node/Express proxy with the official x402-fetch client (EIP-3009 exact scheme):

// npm i express x402-fetch viem
import express from "express";
import { wrapFetchWithPayment } from "x402-fetch";
import { createWalletClient, http } from "viem";
import { base } from "viem/chains";
import { privateKeyToAccount } from "viem/accounts";

const account = privateKeyToAccount(process.env.PAY_WALLET_KEY); // your proxy wallet
const client = createWalletClient({ account, chain: base, transport: http() });
const paid = wrapFetchWithPayment(fetch, client);

const app = express();
app.use(express.json());
app.use((req, res, next) =>                 // your own auth + budget gate
  req.header("authorization") === `Bearer ${process.env.GPT_TOKEN}` && spendOK()
    ? next() : res.status(401).json({ error: "bad token or over budget" }));

app.post("/law-lookup", async (req, res) => {
  const r = await paid("https://royal-ruby-x402.fly.dev/api/law-lookup", {
    method: "POST", headers: { "Content-Type": "application/json" },
    body: JSON.stringify(req.body) });
  res.status(r.status).json(await r.json());
});
app.listen(3000);

Then give the GPT an Action schema pointing at your proxy URL, e.g.:

openapi: 3.1.0
info: { title: "RAEN Legal Research", version: "1.0.0" }
servers: [{ url: "https://your-proxy.example.com" }]
paths:
  /law-lookup:
    post:
      operationId: lawLookup
      summary: "US consumer-law citation lookup (FCRA, FDCPA, TILA, state UDAP)"
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              properties:
                topic: { type: string, description: "e.g. 'FCRA 1681s-b re-dispute window'" }
              required: [topic]
      responses:
        "200": { description: "Structured citations and analysis" }
components:
  securitySchemes:
    bearer: { type: http, scheme: bearer }
security: [{ bearer: [] }]
Free first call (royal-ruby): a wallet that has never paid gets its charge fully rebated after settlement (one per wallet per 30 days) — so the proxy's first law-lookup call is net $0. Set x-payer-address: <your 0x address> on the first request. See the step-by-step guide.

Path 2 — ChatGPT developer mode via MCP

If you're building for developer mode / connectors rather than a store GPT, ChatGPT can attach remote MCP servers. RAEN runs one:

URL:    https://raen-mcp-gateway.fly.dev/mcp
Auth:   Bearer <dev key>
Dev key: POST https://raen-mcp-gateway.fly.dev/keys/request
        (email verification; free, 30-day, rate-limited 3/day/IP)

The gateway fronts 5 tools covering the fleet and is itself x402-gated once the dev key expires — the Bearer key is the billing rail after the free window. Any MCP client (Claude Desktop, Cursor, VS Code agent mode, Goose, OpenHands) uses the same URL — config snippets per client are in the agent directory.

Honest constraints (read before building)

  • A GPT Action cannot pay x402 directly. No wallet, no header-based 402 settlement, no EIP-3009 signing. Path 1 exists precisely because of this — the paying party is your server, not OpenAI's.
  • royal-ruby price experiment: wallets are deterministically bucketed — most see $0.05, some $0.03. The 402 challenge you receive is the exact price you pay; disclosed per TRUTH law in the manifest.
  • tradingagents currently ships a synthetic demo payload, disclosed in its manifest. Don't sell it to users as live market analysis.
  • contract-eye / briefsnap can return a deterministic fallback (mode=statutory-baseline / degraded) when their LLM enhancement is unavailable — responses say so in-band.
  • Information only, not legal advice — royal-ruby and dispute-forge are research/letter-drafting tools.
  • Prices in the table were read from each service's live /.well-known/x402.json and a decoded live 402 challenge ($0.05, scheme exact, eip155:8453, canonical payTo) on publish day; manifests can change — always trust the live 402 quote.

Why bother with a paid API from a GPT at all?

Store GPTs have no revenue mechanism; Actions calling your proxy that calls a per-call-settled API is the cleanest way to put usage-based costs behind a product without subscriptions or Stripe. RAEN's public sales ledger and proof page show every settlement on-chain — the same rails you'd build on.
