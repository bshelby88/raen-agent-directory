Paid API tools for Mastra agents (x402 · Base USDC)

Mastra agents pay per call for real work — no API keys, no signups, no monthly plans. Every endpoint below accepts USDC on Base via the x402 HTTP-native payment protocol: a request without payment gets a 402 challenge; you sign the challenge (EIP-3005 transferWithAuthorization) with your wallet and re-send with a PAYMENT-SIGNATURE header.

Two-POST payment flow (same for every endpoint)

type Challenge = { accepts: Array<Record<string, unknown>> };

async function x402_call(url: string, body: unknown, sign: (c: Challenge) => Promise<string>) {
  // 1) trigger the challenge
  const r = await fetch(url, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify(body),
  });
  if (r.status !== 402) return r.json();
  const challenge: Challenge = JSON.parse(atob(r.headers.get("payment-required")!));
  // 2) sign the exact-scheme challenge with your Base wallet (EIP-3005),
  //    then re-send with PAYMENT-SIGNATURE header
  const sig = await sign(challenge);
  const r2 = await fetch(url, {
    method: "POST",
    headers: { "content-type": "application/json", "PAYMENT-SIGNATURE": sig },
    body: JSON.stringify(body),
  });
  return r2.json();
}

Any EIP-3005 signer works (the official @x402/fetch client wraps this exact flow if you'd rather not hand-roll it). Mastra tool wrappers

Register any endpoint as a Mastra tool (@mastra/core ≥ 0.x, zod schemas). Mastra requires tools to be built with createTool() — plain object tool definitions silently fail to execute:

import { createTool } from "@mastra/core/tools";
import { z } from "zod";
import { Agent } from "@mastra/core/agent";
import { openai } from "@ai-sdk/openai";

const contractAnalyze = createTool({
  id: "raen-contract-analyze",
  description:
    "Paid contract risk analysis ($0.05/call, Base USDC x402). " +
    "Returns risk score, flagged clauses with severity/explanation/suggested edits.",
  inputSchema: z.object({
    text: z.string().describe("Full contract text to analyze"),
    focus: z.array(z.string()).optional().describe("Clauses to focus on, e.g. ['termination']"),
  }),
  execute: async ({ text, focus }) =>
    x402_call("https://contract-eye-x402.fly.dev/api/analyze-contract", { text, focus }, sign),
});

const lawLookup = createTool({
  id: "raen-law-lookup",
  description:
    "Paid US consumer-law citation lookup ($0.05/call, Base USDC x402). " +
    "Returns FCRA/FDCPA/TILA/state-UDAP citations with plain-English summaries. Not legal advice.",
  inputSchema: z.object({ topic: z.string().describe("Legal topic, e.g. 'debt collection'") }),
  execute: async ({ topic }) =>
    x402_call("https://royal-ruby-x402.fly.dev/api/law-lookup", { topic }, sign),
});

export const raenAgent = new Agent({
  name: "raen-analyst",
  instructions:
    "You analyze contracts and cite consumer-protection law. " +
    "The tools are pay-per-call APIs (USDC on Base); call them directly when the task needs them.",
  model: openai("gpt-4o-mini"),
  tools: { contractAnalyze, lawLookup },
});

const result = await raenAgent.generate(
  "Analyze this lease for auto-renewal traps and cite the relevant UDAP statute: ..."
);

A sign implementation uses a viem/account-kit wallet: build the transferWithAuthorization EIP-712 message from challenge.accepts[0] (from, to = payTo, value in USDC base units, validAfter/validBefore, nonce), sign typed data on Base (chain 8453), serialize to the PAYMENT-SIGNATURE header.
