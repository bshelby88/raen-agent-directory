Paid API tools for OpenCode (x402 · Base USDC)

OpenCode — the open-source terminal coding agent from SST — speaks MCP natively over Streamable HTTP remote servers, configured in ~/.config/opencode/opencode.json (global) or opencode.json in the project root, with {env:VAR} interpolation in header values. And because OpenCode is a terminal-native agent that runs shell commands itself, it can also execute the raw wallet-paying x402 flow directly. Two payment paths: the RAEN MCP gateway as a remote MCP server (Path 1, no wallet needed — the Bearer dev key is the billing rail), or the raw two-POST x402 flow run by OpenCode in your repo (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended, no wallet): RAEN MCP gateway in opencode.json

First get a free 30-day dev key (email-verified, self-serve):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then put the key in an environment variable and add the gateway to ~/.config/opencode/opencode.json (or the project's opencode.json):

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "raen": {
      "type": "remote",
      "url": "https://raen-mcp-gateway.fly.dev/mcp",
      "enabled": true,
      "oauth": false,
      "headers": {
        "Authorization": "Bearer {env:RAEN_KEY}"
      }
    }
  }
}

OpenCode expands {env:RAEN_KEY} inside header values, so the Bearer key never has to live in the config file — set it in your shell profile before launching opencode. The "oauth": false flag matters: without it OpenCode may attempt OAuth discovery against the gateway instead of using your Bearer header. Remote servers use the MCP Streamable HTTP transport (exactly what the gateway speaks). You can also add it from inside OpenCode with opencode mcp add raen --url https://raen-mcp-gateway.fly.dev/mcp --header 'Authorization=Bearer {env:RAEN_KEY}'. Tools surface as raen_law_lookup (FCRA/FDCPA/TILA/UDAP statute citations), raen_ticker_analysis, raen_dispute_letter, raen_image_generate, raen_contract_analysis. The gateway's 402 paid gate makes the Bearer key the billing rail — OpenCode pays per MCP tool call without ever touching a wallet. Verify the handshake by asking OpenCode "list your raen tools".

Path 2 (wallet-native): the two-POST x402 flow from OpenCode's shell

OpenCode executes shell commands in your repo as its core primitive, so it can run the raw x402 flow directly — hand it cookbook recipe 02 and it writes the signer verbatim (~30 lines, web3.py):

POST https://royal-ruby-x402.fly.dev/api/law-lookup   (no payment header)
← 402 + payment-required header AND body (base64 JSON: amount, payTo, asset)
# sign USDC transferWithAuthorization (EIP-3009) for that exact amount
POST same URL + x-payment header (base64 signed JSON)
← 200 + result body + x-payment-response (settlement tx on Base)
OpenCode-specific spend guardrails: OpenCode's permission system prompts per shell command — never approve the signer script for "always run": the per-command approval prompt is your hard spend backstop. OpenCode reads AGENTS.md into context every session — put the budget rule there: "never sign an x402 challenge above $1.00 — ask me first". Keep the wallet key as an env var (export RAEN_WALLET_KEY=...) and make sure any script OpenCode writes that reads it is gitignored (.env-style files are exactly what an agent happily commits).
