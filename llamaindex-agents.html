Every endpoint publishes a machine-readable manifest at https://<host>/.well-known/x402.json — read it at call time for the live price and request schema rather than hardcoding either.

Wrapping one as a LlamaIndex tool

x402 is a two-POST flow: the first POST returns 402 with a payment-required header (a challenge naming price, payee, and network); your wallet signs a USDC transferWithAuthorization on Base and you re-send with a PAYMENT-SIGNATURE header. The x402 python SDK handles the signing. LlamaIndex just sees a normal async FunctionTool:

import asyncio, json, base64, httpx
from llama_index.core.tools import FunctionTool
from llama_index.core.agent import ReActAgent
from llama_index.llms.openai import OpenAI

async def law_lookup(topic: str) -> str:
    """Look up US consumer-law citations (FCRA/FDCPA/TILA/UDAP) on a topic.
    Costs $0.05 USDC per call."""
    url = "https://royal-ruby-x402.fly.dev/api/law-lookup"
    body = {"topic": topic}

    async with httpx.AsyncClient(timeout=60) as c:
        # 1) First POST — read the 402 challenge
        r = await c.post(url, json=body)
        if r.status_code != 402:
            return json.dumps({"error": "unexpected status", "status": r.status_code})
        challenge = json.loads(base64.b64decode(r.headers["payment-required"]))
        accepts = challenge["accepts"][0]  # scheme exact, eip155:8453, USDC

        # 2) Sign the USDC transferWithAuthorization (x402 SDK or your signer)
        sig = await sign_x402_payment(accepts, from_key=AGENT_KEY)

        # 3) Re-send with PAYMENT-SIGNATURE
        r2 = await c.post(url, json=body, headers={"PAYMENT-SIGNATURE": sig})
        return r2.text if r2.status_code == 200 else json.dumps({"error": r2.status_code})

law_tool = FunctionTool.from_async_fn(law_lookup)
agent = ReActAgent.from_tools([law_tool], llm=OpenAI("gpt-4o-mini"))
resp = agent.chat("What citations cover bogus 7-year credit reporting?")

Hand the tool to the AgentWorkflow or ReActAgent and the model only spends when the task actually warrants $0.05 — every payment is an on-chain USDC transfer you can reconcile, and LlamaIndex's tool-call schema keeps the arguments validated on top.

The same endpoints also work from an MCP bearer-key gateway if you prefer key-auth to wallet-auth (LlamaIndex speaks MCP via llama_index.tools.mcp), and from LangChain/LangGraph, CrewAI, the OpenAI Agents SDK, PydanticAI, or, Haystack, Semantic Kernel, and n8n with the identical URLs.

Why pay-per-call beats a key/subscription for agent tools

  • Spend follows use: a 100-call run costs ~$5 on the micro-priced endpoints; an idle month costs $0.
  • No credential sprawl: no per-vendor API keys to store, rotate, or leak in your agents' env.
  • On-chain audit trail: every tool call that cost money left a USDC transfer on Base.
  • Works for humans and agents alike: the identical URL serves a LlamaIndex tool, an n8n HTTP node, or an autonomous agent with an x402 wallet.

Honest caveats

  • All-time fleet revenue to date: $0.10 internal test settlements; 0 external payers so far (live ledger: settlement-collector.fly.dev/ledger). You would be early.
  • The tradingagents market-analysis endpoint returns a disclosed synthetic demo payload — do not wire it into money decisions.
  • contract-eye discloses its delivery mode per response: if LLM analysis is unavailable it returns a deterministic rule-based clause scan (fields method / delivery_mode tell you which). briefsnap discloses fallback mode the same way (mode / delivery_mode).
  • The consumer-law endpoint is not legal advice; these are information-only services.
  • Network: Base (eip155:8453), USDC, scheme exact, payTo 0x9b8a…f72f — always verify against the live manifest at call time.
