Paid tools for Rust agents

RAEN runs a fleet of x402 micro-priced API endpoints on Base (USDC). Payment is authentication: no API key, no signup, no account — an HTTP 402 challenge carries the price, you settle on-chain, you retry with the payment header. This page shows two ways to call them from Rust.

Honest framing. Rust has first-class HTTP (reqwest) but the native wallet-signing path needs EIP-3009 transferWithAuthorization signatures. If you do not want to sign payments in-process today, use the MCP-gateway path below with a free 30-day Bearer dev key — the gateway is the billing rail, your code never touches a wallet.

Path 1 (no wallet, recommended): RAEN MCP gateway from any Rust MCP client

The RAEN gateway is a remote streamable-HTTP MCP server at https://raen-mcp-gateway.fly.dev/mcp. Rust MCP SDKs (official rust-sdk / rmcp, and integrations in rig or swiftide) can attach it as a remote tool server with a Bearer header.

Get a free 30-day dev key first — no wallet needed:

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@yourdomain.com"}'

You get a verification link by email, then a 30-day Bearer key. Wire it into rmcp's HTTP transport headers (env var, never committed):

// rmcp streamable-HTTP client with auth header
// RAEN_KEY is read from the environment, never a dotfile
let transport = StreamableHttpClientTransport::with_auth(
    "https://raen-mcp-gateway.fly.dev/mcp".parse()?,
    raen_key, // RAEN_KEY env var
);
// tools appear as raen_law_lookup, raen_dispute_pack, ...

Why the gateway exists: an MCP client cannot answer a 402 challenge. The gateway pays per-call on its own x402 rail and bills via the key, so the Bearer key is the spend surface. Guard it like a credit card.

Path 2 (wallet-native): raw two-POST x402 flow in Rust

For fully on-chain agents, the flow is two POSTs: the first returns 402 with a base64 payment-required header carrying the challenge; you sign a USDC transferWithAuthorization (EIP-3009) against it and retry with an x-payment header. In Rust: reqwest for HTTP, alloy for EIP-3009 signing.

let cli = reqwest::Client::new();
// 1) get the challenge
let r = cli.post("https://royal-ruby-x402.fly.dev/api/law-lookup")
    .json(&serde_json::json!({"topic":"credit-report disputes","state":"LA","scope":"both"}))
    .send().await?;                       // 402
let challenge_b64 = r.headers()["payment-required"].to_str()?;
// 2) decode, sign EIP-3009 transferWithAuthorization with alloy,
//    base64 the payload, retry with x-payment header
// 3) the service settles on-chain and returns 200

Full walkthrough (language-agnostic): x402-cookbook recipe 02.

Rust-specific guardrails: keep the signer key in an env var or OS keyring — never include_str! it into the binary; put a per-call/per-day cap on the signing function; never unwrap() on the 402 decode in production.
