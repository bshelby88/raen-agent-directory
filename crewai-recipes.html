Recipe 1 — Research crew with a per-agent budget guardrail

Wrap the paid call in a custom BaseTool that refuses to spend past a crew-level cap. The guardrail lives in code, not in a prompt, so a looping agent cannot overspend.

import json, urllib.request
from crewai_tools import BaseTool

LEDGER = {"spent": 0.0, "cap": 2.00}  # crew-level cap in USD

def x402_call(url: str, body: dict, price: float) -> dict:
    if LEDGER["spent"] + price > LEDGER["cap"]:
        raise RuntimeError(f"budget cap hit: {LEDGER['spent']:.2f}+{price} > {LEDGER['cap']}")
    # first POST: 402 + payment-required header; second POST: x-payment header
    # (EIP-3009 transferWithAuthorization, see cookbook recipe 02)
    resp = paid_post(url, body)          # your signer here
    LEDGER["spent"] += price
    return resp

class LawLookup(BaseTool):
    name: str = "law_lookup"
    description: str = "US consumer-law citations (FCRA/FDCPA/TILA/UDAP). $0.05/call."

    def _run(self, topic: str) -> str:
        return json.dumps(x402_call(
            "https://royal-ruby-x402.fly.dev/api/law-lookup",
            {"topic": topic}, 0.05))

Recipe 2 — Contract-review crew (paralegal pattern)

Split analysis and drafting into two agents so the paid call happens exactly once, on validated input:

from crewai import Agent, Task, Crew

paralegal = Agent(
    role="Paralegal",
    goal="Extract contract text and file it for analysis",
    tools=[],                    # no paid tool — free agent
    llm="gpt-4o-mini")

analyst = Agent(
    role="Contract analyst",
    goal="Flag risky clauses with severity and suggested edits",
    tools=[contract_eye_tool],   # the $0.05 paid tool from crewai-agents.html
    llm="gpt-4o-mini")

crew = Crew(
    agents=[paralegal, analyst],
    tasks=[
        Task(description="Prepare {contract_text} for analysis", agent=paralegal),
        Task(description="Analyze the prepared contract via analyze-contract", agent=analyst),
    ])

Cost discipline: one analyst run = one $0.05 settle. If a task might retry, put the paid tool call behind an idempotency check (cache by input hash) so retries are free.

Recipe 3 — Dispute-letter pipeline crew (the $0.10 pack)

# packer agent calls dispute-forge once per consumer, gets 3 letters + 12 citations
# verify the settle on-chain before declaring the task done:
#   curl https://settlement-collector.fly.dev/ledger.json | jq '.recent[] | select(.payer=="")'
class DisputePack(BaseTool):
    name: str = "dispute_pack"
    description: str = "3 dispute letters + citations. $0.10. Returns delivery/claim info."
    def _run(self, facts: str) -> str:
        r = x402_call("https://dispute-forge-x402.fly.dev/api/dispute-pack",
                      {"facts": facts}, 0.10)
        return r.get("claim_url", json.dumps(r))

Recipe 4 — Dispatch-first crew (route, don't hardcode)

When a crew's task mix is unknown at build time, give it one $0.50 dispatch tool plus the per-service tools; dispatch classifies the intent and returns the right endpoint, the crew calls the cheap specialists directly after the first route.

Recipe 5 — First-call-free onboarding for your crew

royal-ruby/law-lookup runs charge-and-rebate: the first call charges $0.05 and rebates it, so a new crew can validate the whole rail for a net-$0 probe before you wire the budget. Point your first-ever task at that endpoint.

Honest constraints

  • Your crew needs a wallet signer for the second POST (EIP-3009 transferWithAuthorization) — CrewAI does not pay 402s natively. Keep the key in an env var, never in agent memory or repo files, and never "always-allow" the signer command in an autonomous loop.
  • Alternative without a wallet: run the crew against the RAEN MCP gateway (raen-mcp-gateway.fly.dev/mcp) with a free 30-day Bearer dev key — POST https://raen-mcp-gateway.fly.dev/keys/request. The gateway's 402-paid gate makes the key the billing rail.
  • Some surfaces disclose degraded/synthetic modes in their manifests (tradingagents demo payload) — the ledger and manifests are the source of truth, not marketing.
