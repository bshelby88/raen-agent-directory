Paid API tools for Roo Code (x402 · Base USDC)

Roo Code (formerly Roo Cline) — the open-source autonomous coding agent for VS Code with its own modes engine (Code / Architect / Ask / Debug + custom modes) — speaks MCP natively with support for remote streamable-HTTP servers and custom request headers, which makes it a natural host for the RAEN paid-tool catalog. Two payment paths: the RAEN MCP gateway added as a remote MCP server (Path 1, no wallet needed — the Bearer dev key is the billing rail), or the raw two-POST x402 flow executed from Roo Code's terminal with your wallet (Path 2). Everything below accepts USDC on Base via the x402 HTTP-native payment protocol.

Path 1 (recommended, no wallet): RAEN MCP gateway as a remote MCP server

First get a free 30-day dev key (email-verified, self-serve):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'
# → check your inbox for the verification link + key

Then add the gateway in Roo Code: open the MCP Servers view in the Roo Code sidebar → switch to the Installed tab → Edit Global MCP (or per-project .roo/mcp.json) → add a remote server:

"raen": {
  "type": "streamable-http",
  "url": "https://raen-mcp-gateway.fly.dev/mcp",
  "headers": { "Authorization": "Bearer ***" },
  "disabled": false
}

This lands in mcp_settings.json (global config lives under your Roo Code settings dir; project-level in .roo/mcp.json) — keep the key out of any committed file; paste the Bearer value from your inbox and treat the settings file as a secret. Roo Code calls the tools through use_mcp_tool with server name raen: raen_law_lookup (FCRA/FDCPA/TILA/UDAP statute citations), raen_ticker_analysis, raen_dispute_letter, raen_image_generate, raen_contract_analysis. The gateway's 402 paid gate makes the Bearer key the billing rail — Roo Code pays per MCP tool call without ever touching a wallet. Verify the handshake by asking Roo "list your raen tools".

Path 2 (wallet-native): the two-POST x402 flow from Roo Code's terminal

Roo Code executes bash and python in its VS Code terminal, so it can run the raw x402 flow directly — hand it cookbook recipe 02 and it writes the signer verbatim (~30 lines, web3.py):

POST https://royal-ruby-x402.fly.dev/api/law-lookup   (no payment header)
← 402 + payment-required header AND body (base64 JSON: amount, payTo, asset)
# sign USDC transferWithAuthorization (EIP-3009) for that exact amount
POST same URL + x-payment header (base64 signed JSON)
← 200 + result body + x-payment-response (settlement tx on Base)
Roo-Code-specific spend guardrails: Roo Code's auto-approve settings can run MCP tools (and terminal commands) without asking — and its Max Requests cap is a loop guard, not a spend cap. Before enabling wallet-path payments, leave MCP tools auto-approval OFF (or scope it to specific tools), keep terminal auto-approval off, and load the wallet key as an env var (export RAEN_WALLET_KEY=...) rather than letting Roo write a key into any file. Roo Code reads rules from .roo/rules/ (or a .roorules file) every task — put the budget rule there: "never sign an x402 challenge above $1.00 — ask me first". If you use a custom mode for paid work, define it in .roomodes so the spend rule travels with the mode. Interactive approval is the hard backstop.
