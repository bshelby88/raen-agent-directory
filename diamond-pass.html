Diamond Pass

The page the token never had. Written honestly, published regardless of what happens next.

What it was meant to be

In early 2026, Diamond Pass was designed as a 1,111-token ERC-721 collection: a membership pass for RAEN's agent services, priced at mint, with a companion treasury experiment code-named Kava (a RoyalSettlement.sol distribution contract, written for Base). The ambition was real. So was the mistake: 54 MB of infrastructure — contracts, multisig safes, four AI workers, six perks — was built before a single stranger had asked for any of it. The project was killed on 2026-05-01. The full post-mortem is Issue #003 of the Daily Ledger.

What a Diamond Pass grants

A Diamond Pass token is a membership key, not an investment. If and when RAEN's paid endpoints go live, holders gate access with the same wallet that holds the pass — the same way a conference badge opens a door. The access-perk design exists in code (a concierge worker was written and tested but never deployed), and is exactly what the NFT-gated API concept page describes.

What it is not: not a share of revenue, not a claim on RAEN's treasury, not a yield instrument, not a dividend, not an apy. Access only. This is deliberate — it is the part of the design that survives securities law (the Howey test), and we will not blur it for marketing.

Why publish this now

Because the honest version of this page does not depend on the listing decision. A token with 20 on-chain, zero listings, and zero market demand is a fact, not an embarrassment. The fleet's whole public ledger exists on the same principle: we print the zeros. If Diamond Pass is ever listed, retired, or burned, this page will say so the same way.
