Paid API tools for Zed agents

Zed's agent panel can call real, metered web services through MCP. RAEN runs 12 production x402 services on Base Mainnet (USDC, pay-per-call, $0.01–$5.00) plus a Bearer-gated MCP gateway exposing 5 flagship tools. No subscription, no API key vendor: the HTTP 402 challenge is the pricing, and payment is the authorization.

Path 1 — No wallet: the RAEN MCP gateway (recommended)

The gateway at https://raen-mcp-gateway.fly.dev/mcp is a Streamable-HTTP MCP server. Get a free 30-day dev key (email verification, self-serve, no waiting):

curl -X POST https://raen-mcp-gateway.fly.dev/keys/request \
  -H 'Content-Type: application/json' \
  -d '{"email":"you@example.com"}'

Add it to ~/.zed/settings.json as a remote context server:

{
  "context_servers": {
    "raen": {
      "enabled": true,
      "url": "https://raen-mcp-gateway.fly.dev/mcp",
      "headers": { "Authorization": "Bearer YOUR_DEV_KEY" }
    }
  }
}

Remote (HTTP) MCP server support in Zed is version-dependent — earlier Zed releases only supported stdio servers via extensions. If your build rejects url, upgrade Zed or use Path 2. Put the dev key in an environment variable and reference it where your setup allows; never commit a key into the repo Zed has open. Tools appear as raen_law_lookup, raen_ticker_analysis, raen_dispute_letter, raen_image_generate, raen_contract_analysis.

Path 2 — Wallet-native: raw x402 from Zed's terminal

Zed's agent can run shell commands, so it can run the raw two-POST x402 flow itself: POST an unpaid request, receive HTTP 402 with a payment-required challenge (EIP-3009 transferWithAuthorization, USDC on Base), sign, then resend with the payment header. Full working recipes: x402 Integration Cookbook (recipe 02 is the Python client).

Zed-specific spend guardrails: the agent panel's project trust decides what it can run unattended — keep the wallet key as an environment variable (never pasted into the panel, never in project files), add a budget rule to .zed/ project instructions or your rules file so the price ceiling is in context every session, and treat terminal-command approvals as the per-call spend backstop. Never auto-approve a loop that calls paid tools.
